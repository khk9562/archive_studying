사내 48번 서버에 솔루션을 설치 테스트하면서 `ls -la ~` 출력을 읽다가 정리한 내용이다.


## 1. `ls -la` 출력 읽는 법


```plain text
-rw------- 1 root    root    11355 Oct 28 00:00 ocp-link.env
drwxrwxr-x 9 회사B  회사B   4096 Oct 29 23:06 media
```


| 칸 | 예              | 뜻                                             |
| - | -------------- | --------------------------------------------- |
| 1 | `-rw-------`   | 종류(첫 글자) + 권한(나머지 9글자)                        |
| 2 | `1`            | 링크 수. 폴더는 하위 폴더 수에 따라 커진다. 신경 쓸 일은 드물다        |
| 3 | `root`         | 소유자(user)                                     |
| 4 | `root`         | 그룹(group)                                     |
| 5 | `11355`        | 크기(바이트). 폴더는 보통 `4096` 으로 고정이라 안의 용량을 뜻하지 않는다 |
| 6 | `Oct 28 00:00` | 마지막 수정 시각. 올해가 아니면 시각 자리에 연도가 나온다             |
| 7 | `ocp-link.env` | 이름                                            |

- `ls -la`: `-l` 자세히, `-a` 숨김 파일까지
- `ls -laF`: 폴더 끝에 `/`, 링크 끝에 `@`, 실행 파일 끝에 `*` 를 붙여 준다
- `ll`: `ls` 의 별칭(alias)이고 배포판마다 다르다. Ubuntu 기본은 `ls -alF`(숨김 파일 보임), RHEL 계열은 `ls -l`(숨김 파일 안 보임). `alias ll` 로 확인한다

## 2. 폴더와 파일 구분: 첫 글자로 본다


| 첫 글자 | 종류                                                   |
| ---- | ---------------------------------------------------- |
| `d`  | 폴더(directory)                                        |
| `-`  | 일반 파일                                                |
| `l`  | 심볼릭 링크. `current -> releases/<번들>` 처럼 화살표로 대상을 보여 준다 |


터미널에서 파란 글씨가 폴더인 경우가 많지만 색은 설정에 따라 다르니 보조로만 본다.


## 3. 확장자

- 리눅스에서 확장자는 **이름의 일부**일 뿐이다. 시스템은 확장자로 파일 종류를 정하지 않는다
- 그래서 확장자로 폴더 · 파일을 가를 수 없다
    - `.config` · `.ssh` 는 확장자처럼 보이지만 폴더다
    - `.sudo_as_admin_successful` 은 확장자가 없지만 파일이다
- 확장자는 사람과 프로그램에게 주는 힌트다. `.log` 는 로그, `.env` 는 `KEY=값` 설정, `.tar.gz` 는 tar 로 묶고 gzip 으로 압축한 파일이라는 관례

## 4. 숨김 파일과 `.` · `..`

- 이름이 `.` 으로 시작하면 숨김 파일 · 폴더다. `ls` 에는 안 보이고 `ls -a` 에 보인다. 예: `.bashrc`, `.ssh/`, `.env`
- `.` = 지금 폴더, `..` = 한 단계 위 폴더. `cd ..` 은 위로 올라가기

## 5. 경로


| 표기                  | 뜻                                    |
| ------------------- | ------------------------------------ |
| `/`                 | 최상위(root) 폴더. 모든 경로의 출발점             |
| `~`                 | 내 홈 폴더. `회사B` 계정이면 `/home/회사B` |
| `/프로젝트S/sc-cloud` | 절대 경로. `/` 부터 시작해 어디서 쳐도 같은 곳        |
| `media/`            | 상대 경로. 지금 있는 폴더 기준                   |

- `pwd`: 지금 있는 폴더 출력
- `scp 파일 회사B@<ip주소>:` 처럼 콜론 뒤를 비우면 그 계정의 홈으로 간다

## 6. 권한 · 소유자


권한 9글자는 3글자씩 **소유자 / 그룹 / 그 밖의 계정** 순서다. `r` 읽기, `w` 쓰기, `x` 실행(폴더는 들어가기), `-` 없음.


숫자로는 r=4, w=2, x=1 을 더해 세 자리로 쓴다.


| 숫자    | 글자          | 쓰임                                       |
| ----- | ----------- | ---------------------------------------- |
| `600` | `rw-------` | 소유자만 읽고 쓰기. 토큰 · 비밀번호 파일(`ocp-link.env`) |
| `644` | `rw-r--r--` | 누구나 읽기, 소유자만 쓰기. 일반 설정 파일                |
| `664` | `rw-rw-r--` | 그룹도 쓰기. `scp` 로 받은 파일이 흔히 이렇게 놓인다        |
| `700` | `rwx------` | 소유자만 들어가는 폴더(`secrets/`)                 |
| `755` | `rwxr-xr-x` | 누구나 들어가고 실행, 소유자만 쓰기. 일반 폴더 · 스크립트       |

- `chmod 600 파일`: 권한 바꾸기
- `chown root:root 파일`: 소유자:그룹 바꾸기
- `root`: 리눅스의 최고 관리자 계정. `sudo 명령` 은 그 명령 하나만 root 로 실행한다
- root 소유 600 파일은 일반 계정이 못 읽는다. 그래서 `ocp-link.env` 를 읽는 `setup.sh` 는 `sudo` 로 실행한다

## 7. 심볼릭 링크


다른 파일 · 폴더를 가리키는 바로가기. 설치본의 `/프로젝트S/sc-cloud/current` 가 `releases/<지금 판>` 을 가리킨다. 업그레이드는 새 폴더를 만들고 링크만 바꿔 가리키게 한다.

- `readlink /프로젝트S/sc-cloud/current`: 링크가 가리키는 곳 출력

## 8. 이번에 쓴 명령


| 명령                        | 하는 일                                  |
| ------------------------- | ------------------------------------- |
| `ssh 회사B@<ip주소>` | 서버 접속                                 |
| `scp 파일 회사B@서버:경로`     | 내 PC → 서버로 파일 복사                      |
| `cd 경로` · `pwd`           | 폴더 이동 · 지금 위치                         |
| `mkdir -p 경로`             | 폴더 만들기(중간 폴더까지, 이미 있으면 그냥 넘어감)        |
| `cp` · `mv` · `rm`        | 복사 · 이동(이름 바꾸기) · 삭제. `rm` 은 휴지통이 없다  |
| `cat 파일`                  | 파일 내용 출력. 토큰 파일에는 쓰지 않는다              |
| `find 경로 -maxdepth 2`     | 하위 폴더까지 목록. `tree -L 2` 가 있으면 그림으로    |
| `tar -xzf 묶음.tar.gz`      | 압축 풀기(x 풀기, z gzip, f 파일 지정)          |
| `sha256sum -c 파일.sha256`  | 받은 파일이 깨지지 않았는지 검사. `OK` 여야 한다        |
| `명령 2>&1 | tee 로그`        | 화면에 보이면서 파일에도 남기기. `2>&1` 은 오류 출력도 함께 |
| `echo $?`                 | 바로 앞 명령의 종료 코드. 0 이면 성공               |


### 자세히: `sha256sum` · `tar -xzf` · `chown`


설치 3단계에서 차례로 쓴다. 받은 번들을 **검사하고(****`sha256sum`****) → 풀고(****`tar -xzf`****) → 토큰 파일의 주인을 바꾼다(****`chown`****)**.


`sha256sum`: 파일이 깨지거나 바뀌지 않았는지 검사

- 파일 내용을 SHA-256 으로 계산해 64자짜리 값(해시)을 만든다. 내용이 1바이트만 달라도 값이 완전히 달라진다
- 번들을 만든 쪽이 미리 계산한 값을 `<번들>.tar.gz.sha256` 에 적어 함께 보낸다
- `sha256sum -c <번들>.tar.gz.sha256` 은 받은 파일을 다시 계산해 적힌 값과 비교한다
    - `<번들>.tar.gz: OK` → 전송 중에 깨지지 않았다
    - `FAILED` → 받다가 끊겼거나 다른 파일이다. 다시 받는다
- «깨지지 않았는가» 만 본다. «누가 만들었는가» 는 바로 뒤의 `bundle-trust.sh fingerprints`(서명 지문 대조)가 확인한다

`tar -xzf`: 묶음 파일 풀기

- `tar` 는 여러 파일 · 폴더를 파일 하나로 묶고 푸는 도구다. `.tar.gz` 는 tar 로 묶은 뒤 gzip 으로 압축했다는 뜻(Windows 의 `.zip` 과 비슷)

| 글자  | 뜻                              |
| --- | ------------------------------ |
| `x` | 풀기(extract). 묶을 때는 `c`(create) |
| `z` | gzip 압축을 함께 풂                  |
| `f` | 뒤에 오는 이름이 대상 파일(file)          |

- `tar -xzf <번들>.tar.gz` → 지금 폴더에 `<번들>/` 폴더가 생긴다
- `-C 경로` 를 붙이면 그 경로에 푼다. 업그레이드 때 `tar -xzf … -C /프로젝트S/sc-cloud/releases`
- 풀기 전에 목록만 보기: `tar -tzf <번들>.tar.gz` (`t` = list)

`chown`: 파일 소유자 바꾸기

- change owner 의 줄임말. 형식은 `chown 소유자:그룹 파일`
- `sudo chown root:root ~/ocp-link.env` → 소유자와 그룹을 모두 `root` 로. 소유자를 남에게 넘기는 일이라 `sudo` 가 필요하다
- 보통 `chmod`(권한 바꾸기)와 짝으로 쓴다
    - `chown root:root` → 주인을 root 로
    - `chmod 600` → 주인만 읽고 쓰게
    - 둘을 합치면 «root 만 읽을 수 있는 파일». `scp` 로 받은 파일은 `회사B` 소유 664(그룹도 쓰기 가능)로 놓이기 때문에, 토큰 파일을 잠그려고 이 두 줄을 친다
- 폴더 안까지 한꺼번에 바꾸려면 `chown -R`. 범위가 넓으니 경로를 꼭 확인한다

### 자세히: `ssh` · `scp`


둘 다 내 PC(Mac) 에서 서버로 닿는 명령이다. `ssh` 는 서버에 **들어가고**, `scp` 는 그 연결로 파일을 **나른다**. 둘 다 암호화된 연결을 쓴다.


`ssh`: 서버에 접속해서 명령 치기

- Secure Shell 의 줄임말. 형식은 `ssh 계정@서버주소`
- `ssh 회사B@<ip주소>` → 비밀번호를 물으면 입력한다. 치는 동안 화면에 아무것도 안 찍히는 것이 정상이다
- 접속되면 프롬프트가 `회사B@kecp-3:~$` 처럼 바뀜다. 이제부터 치는 명령은 서버에서 돈다. 가이드의 `[Mac]` · `[서버]` 표시는 이 프롬프트로 구분한다
- 나가기: `exit` 또는 `Ctrl` + `D` → 다시 Mac 프롬프트로 돌아온다
- 명령 하나만 서버에서 실행하고 바로 돌아오기: `ssh 회사B@<ip주소> "mkdir -p ~/media"`
- 포트가 22번이 아니면 `ssh -p 2222 계정@서버` (소문자 `-p`)

처음 접속할 때 나오는 질문


```plain text
The authenticity of host '<ip주소>' can't be established.
ED25519 key fingerprint is SHA256:....
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

- «이 서버를 처음 본다, 진짜 그 서버가 맞느냐» 는 질문이다. `yes` 를 치면 서버의 지문이 Mac 의 `~/.ssh/known_hosts` 에 저장되고 다음부터는 묻지 않는다
- 나중에 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` 가 나오면 저장된 지문과 서버 지문이 다르다는 뜻이다. OS 를 다시 깔았는지 담당자에게 먼저 확인하고, 맞으면 `ssh-keygen -R <ip주소>` 로 옛 지문을 지운 뒤 다시 접속한다

`scp`: 서버와 파일 주고받기

- Secure Copy 의 줄임말. ssh 연결 위에서 `cp` 를 하는 셈이다
- 형식은 `scp 출발 도착`. **앞이 보내는 쪽, 뒤가 받는 쪽**
- 주소 뒤에 `:` 이 붙은 쪽이 서버다

| 명령 (Mac 에서 실행)                                            | 하는 일                           |
| --------------------------------------------------------- | ------------------------------ |
| `scp ocp-link.env 회사B@<ip주소>:`                   | Mac → 서버 홈(`/home/회사B`)     |
| `scp a.tar.gz a.tar.gz.sha256 회사B@<ip주소>:media/` | 여러 파일을 서버 `~/media/` 로         |
| `scp 회사B@<ip주소>:setup.log .`                     | 서버 → Mac 의 지금 폴더(`.`)          |
| `scp -r 폴더 회사B@<ip주소>:`                          | 폴더째 보내기(`-r`)                  |
| `scp -P 2222 파일 계정@서버:`                                   | 22번이 아닌 포트. scp 는 **대문자** `-P` |

- `:` 뒤를 비우면 그 계정의 홈, `/` 없이 적은 경로(`media/`)는 홈 기준이다
- 파일마다 `100%` 가 찍히고 프롬프트로 돌아오면 성공이다

자주 하는 실수

- **서버 안에서** **`scp`** **를 치는 것.** `scp` 는 파일이 있는 Mac 쪽에서 친다. 프롬프트가 `회사B@kecp-3` 이면 `exit` 로 나온 뒤 친다
- **`:`** **를 빠뜨리는 것.** `scp 파일 회사B@<ip주소>` 은 서버로 가지 않고 Mac 에 `회사B@<ip주소>` 이라는 이름의 파일을 만든다
- 받는 쪽에 같은 이름이 있으면 **묻지 않고 덮어쓴다**
- 받은 파일은 접속한 계정(`회사B`) 소유로 놓인다. 48번에서는 664 였다. 토큰 파일은 받은 뒤 `chown` · `chmod` 로 잠근다(위 `chown` 항목)

## 9. vi 편집기


서버에는 보통 GUI 편집기가 없어서 `vi` 로 설정 파일을 고친다. `vi ~/site.conf` 로 연다. root 소유 파일은 `sudo vi 파일`.


### 모드 세 가지


| 모드     | 들어가는 법           | 하는 일                               |
| ------ | ---------------- | ---------------------------------- |
| 일반 모드  | 처음 열었을 때 · `Esc` | 이동 · 삭제 · 복사. 키가 글자가 아니라 명령으로 동작한다 |
| 입력 모드  | `i` · `a` · `o`  | 글자 입력. 화면 아래에 `-- INSERT --`       |
| 명령행 모드 | 일반 모드에서 `:`      | 저장 · 종료 · 치환                       |


헷갈리면 `Esc` 를 눌러 일반 모드로 돌아온다.


### 저장 · 종료


| 키               | 뜻                |
| --------------- | ---------------- |
| `:w`            | 저장               |
| `:wq` (또는 `ZZ`) | 저장하고 나가기         |
| `:q`            | 나가기(바꾼 게 있으면 거부) |
| `:q!`           | 저장하지 않고 나가기      |


### 입력 모드로 들어가기


| 키   | 뜻               |
| --- | --------------- |
| `i` | 커서 앞에 입력        |
| `a` | 커서 뒤에 입력        |
| `o` | 아래에 새 줄을 만들고 입력 |
| `A` | 줄 끝에서 입력        |


### 이동 (일반 모드)


| 키                    | 뜻                             |
| -------------------- | ----------------------------- |
| `h` `j` `k` `l`      | 왼쪽 · 아래 · 위 · 오른쪽 (화살표 키도 된다) |
| `0` · `$`            | 줄 처음 · 줄 끝                    |
| `gg` · `G`           | 파일 처음 · 파일 끝                  |
| `:30`                | 30번째 줄로                       |
| `/BUNDLE`  • `Enter` | 아래로 검색. `n` 다음, `N` 이전        |


### 편집 (일반 모드)


| 키             | 뜻           |
| ------------- | ----------- |
| `x`           | 커서 글자 하나 삭제 |
| `dd`          | 줄 삭제(잘라 두기) |
| `yy`          | 줄 복사        |
| `p`           | 아래에 붙여 넣기   |
| `u`           | 되돌리기        |
| `Ctrl`  • `r` | 다시 하기       |
| `:%s/옛값/새값/g` | 파일 전체에서 바꾸기 |
| `:set nu`     | 줄 번호 보이기    |


### 주의

- Mac 에서 복사한 값은 **입력 모드에서** `Cmd+V` 로 붙여 넣는다. 일반 모드에서 붙여 넣으면 글자들이 명령으로 실행돼 파일이 망가진다
- 망가졌으면 `:q!` 로 저장 없이 나가서 다시 연다
- 열 때 `E325: ATTENTION` 이 나오면 같은 파일을 다른 창에서 열고 있거나, 지난번 vi 가 비정상 종료돼 `.파일명.swp` 가 남은 것이다. 다른 창이 없으면 `D`(swap 삭제)를 고르고, 확실하지 않으면 `Q` 로 나간다
- `site.conf` 처럼 같은 키가 두 번 나오면 안 되는 파일은, 끝에 새 줄을 덧붙이지 말고 있는 줄을 고친다. `#` 로 막힌 줄은 `#` 를 지운다
- 고친 뒤 실제 값만 보기: `grep -v '^#' ~/site.conf | grep -v '^$'`
